# 可靠性修复与使用说明

这轮改动针对停止、会话切换、消息送达、存储恢复和自动修复的具体缺陷。现有运行时升级保留，未更换数据库，也不改变用户选择的模型。

## 会话与停止

- 模型透传命令进入与普通消息相同的调度路径，后续停止、审批、回答和其他聊天可以继续被接收。
- `/stop` 同时取消正在合并、排队和追加的消息；已经运行的回合进入取消与清理。
- `/new`、`/bind` 隔离旧回合，迟到事件不能写回新绑定或关闭新卡片。
- 核心停止先停止接收新任务，再有界等待清理。外部服务是否实际完成中断与本地任务状态分开判断，不能把本地超时理解为外部副作用已经撤销。

## 回答发送失败时

先用 `/status` 查看待发回答，再使用：

```text
/retry
/retry <投递ID>
```

省略 ID 会选择当前聊天/用户最近一条未完成记录；指定 ID 也会检查来源。补发只处理尚未确认成功的分段，不重新调用模型。聊天有模型任务正在运行时先等待该任务结束。

JSON 文件宿主会在发送前保存记录，并在每个分段成功后保存进度。保存失败不会被当成发送成功。已送达记录清除重复正文并限制元数据保留，完整会话历史仍按原有机制保存。

自定义宿主需要实现 `saveResponseDelivery`、`getResponseDelivery`、`listResponseDeliveries` 和 `flush` 才有持久待发能力；否则只提供本进程内的待发记录，状态会明确提示重启可能丢失。

平台收到消息之后、本地保存成功之前仍可能发生进程中断。网络超时也可能无法确定平台是否已收到；这时先核对聊天内容再手工补发，系统不会把超时当成明确拒绝后立即重复发送。

## 飞书

- 长回答按序列化请求体的 UTF-8 字节预算分段，跨分段代码块补齐围栏，避免把中文字符数当作卡片容量。
- 审批或问答处理后，原卡按真实结果更新；审批提示发送或登记失败会结束本次等待。
- 过期状态来自权限网关的真实超时事件，不再另外猜一个卡片有效期。
- 卡片创建、收尾及 typing 状态检查具体回合归属，旧操作不能更新新回合。
- 不支持的附件和部分下载失败会明确提示；全部附件失败时不会假装已将材料交给模型。

## 存储与进程退出

Store 使用同目录临时文件写入并原子替换，保留上一份有效 `.bak`。主文件损坏但备份有效时可加载备份，并在后续保存前保留损坏原件；没有有效备份时拒绝空载启动，不覆盖旧文件。读取权限错误、写入失败也会明确报告。

正常停机调用 `close()`，等待已有变更落盘；致命异常或停机失败以非零退出。超过停机期限会明确报告可能仍有未落盘变更。残留的临时文件或损坏原件用于恢复，不在启动时批量清除。

## 工作流恢复与修复候选

新工作流记录唯一执行者，恢复前检查主机、PID 和 owner token。活跃执行者不能被另一请求抢占；能确认旧执行者退出时才恢复。损坏锁、其他主机或无法确认的归属需要人工核对，错误会说明原因。

旧版本遗留的 `running` 任务没有执行者证据，因此不会盲目接管；需要先确认旧进程退出，再处理旧任务状态或重新发起审查。已有旧快照如果缺少冻结 `head_tree`，自动修复会要求重新审查，旧产物保持原样。

自动修复有以下变化：

- 每次尝试独立保存工作树、分支、候选提交、结果 JSON 和完整补丁，不隐式删除上次产物。
- 审查正文、diff 和修复工作树使用一致的冻结版本。
- 只在目标范围内产生的修改才可形成候选；一组失败后保留现场并停止后续组，避免夹带失败残留。
- **修复候选不等于已验证修复。** 没有配置问题验证器时，输出候选数量，`fixedCount` 不会虚增。
- 完整补丁使用保存的精确 base/head 计算，不按文件数量猜测 `HEAD~N`。

应用候选前先检查补丁、运行相关验证，并确保目标仓库包含原先被审查的改动。审查 staged/unstaged 时，先妥善保存这些原始改动，不能仅为了“工作区干净”把它们丢弃或移走。随后按输出的实际候选提交应用；工具不会在当前工作区自动合并。

## 运行边界

本轮验证使用隔离 mock 和本地构建，没有发送真实模型/飞书请求，没有处理真实会话数据或重启正在运行的桥接。代码在桥接加载新构建后生效。模型选择面板、全量运行时事件重构、预算系统和数据库迁移属于后续改进，不属于本次缺陷修复。
