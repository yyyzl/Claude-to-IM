# 在飞书查看 Codex 账号额度

在使用内置 Codex runner 的机器人聊天中发送：

```text
/quota
```

查询通过当前 runner 的 `codex app-server` 连接读取账号额度。每次命令都会主动读取，并显示本次查询时间；不需要发起模型对话。已有 `/usage` 继续显示桥接统计的 Token 用量，`/status` 继续显示桥接运行状态。

## 报告内容

- 当前 Codex 登录账号的额度桶和服务端提供的窗口。
- 各窗口已用、剩余百分比及重置时间；时间使用北京时间。
- 300 分钟窗口显示为 5 小时，10080 分钟窗口显示为周，其它周期按实际时长显示。
- 服务端未提供周期或重置时间时明确说明；窗口缺失不代表剩余 100% 或无限额度。

额度属于 **runner 使用的登录账号**，同一账号的其它项目和客户端也会消耗它。它不是当前飞书聊天或当前工作目录的独立额度。不同套餐和后端可能返回不同窗口，未必同时有 5 小时和周窗口。

重置时间是服务端给出的下一次重置时间。时间已到时应重新查询，以新结果为准；仅凭时间不能判断账号已经恢复使用资格。

## 使用与限制

- `/quota` 不需要参数；机器人命令形式 `/quota@机器人名` 也可使用。
- 模型正在执行时仍可查询；查询不创建或切换会话、不改变模型与权限，也不计入本地模型 Token 统计。
- 桥接停机后不再发起旧查询的后续回执或分块；已经进入平台的发送请求仍可能完成。
- Claude 后端或没有实现额度能力的外部宿主会明确提示不支持。
- 未登录、账号/提供商不支持订阅额度、网络失败或返回数据错误时会提示查询失败。接口存在不等于所有账号都能返回数据。
- 报告只展示额度白名单字段，不显示邮箱、账号 ID、认证信息或原始响应。
- 本功能只提供手动查询；账号管理、自动预警、购买积分和额度重置操作不在此入口中。

运行中的旧桥接需要切换到包含本功能的新构建后才能识别命令。部署和重启应在方便时单独安排。

## 宿主接入

可选能力定义在 [LLMProvider](../src/lib/bridge/host.ts)。内置 Codex provider 使用固定版本公开 RPC `account/rateLimits/read`，通过既有握手、超时和连接代际校验读取额度；不创建第二套账号 HTTP 客户端。

自动验证使用纯内存的 app-server 和飞书传输，覆盖字段校验、报告格式、共享连接错误隔离及控制消息消费。离线回归通过不代表真实账号与运行中的飞书已联调。

参考：[Codex app-server 协议](https://learn.chatgpt.com/docs/app-server)、[套餐与额度说明](https://learn.chatgpt.com/docs/pricing)。
