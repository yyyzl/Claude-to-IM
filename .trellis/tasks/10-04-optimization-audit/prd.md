# 项目整体优化审查

用户要求在完成运行时升级后，仔细研究项目可优化之处。本轮产出基于当前工作树的证据、优先级及渐进实施路线，不进行未经讨论的架构重写。

## 范围

- 消息入口、任务队列、会话状态、取消、恢复与并发一致性。
- JSON 宿主存储、工作流审查/自动修复的可靠性与性能。
- 飞书交互、消息投递、长回复、附件、审批和用户问答体验。
- 运行时边界、配置装配、发布运维、契约测试与可观测性。

## 验收

- 每项重要发现附触发场景、源码位置、用户影响、建议方案、验证方法和优先级。
- 区分已证实缺陷、结构性风险、体验机会；不将假设写成已发生事故。
- 先依据本地代码与已有测试；外部建议仅在必要时核对官方来源。
- 纯只读分析业务代码；研究文件可写入本任务 research/。不读取凭据、生产日志、真实会话，不调用模型或飞书生产 API。
- 需要复现时仅使用已明确注入的内存 mock；测试在隔离 Node test 环境执行，后台总时长小于 60 秒。
- 保留当前未提交升级改动及用户原有文件，GitNexus 旧索引不能替代当前源码证据。

## 研究分工

- lifecycle：bridge manager / router / conversation engine / locks 的运行生命周期。
- storage-workflow：宿主存储与工作流持久化、自动修复和性能。
- feishu-delivery：飞书、渲染、delivery 与交互体验。
- 主线程：运行时与配置/测试/运维横切审查，核验高优先级发现并合并路线。
