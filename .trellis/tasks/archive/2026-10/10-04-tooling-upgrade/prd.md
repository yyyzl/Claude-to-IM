# Trellis 与 GitNexus 工具链更新

用户授权提交并推送现有成果，并更新本机和当前项目使用的 Trellis、GitNexus。

## 验收

- 已完成的模型运行时升级与可靠性修复提交并推送到 `origin/main`。
- 核对官方发布渠道与实际安装来源，升级适用的稳定版；项目若使用 Trellis beta，核对 beta 是否比稳定版更新后选择，不能仅凭版本字符串降级。
- 升级前确认 CLI 更新影响，保留 Fusion、自定义 hooks、开发规范、用户身份和任务状态；不覆盖无关全局配置。
- 更新项目托管模板、技能和上下文；冲突先比对合并，禁止 blanket force 覆盖。
- GitNexus 在最后提交后重建当前项目索引，保留已有 embeddings，验证 status/query/context/impact 等关键能力。
- 对工具工作流做对应最小验证，记录版本、官方来源、更新结果和剩余限制；提交并推送本次项目内的更新。

## 边界

不启动桥接或真实模型/飞书；不读凭据、生产会话或日志。不使用 Git force push、reset/clean、强删用户文件。更新这两个已明确指定的全局 CLI 属于用户授权范围。其他全局配置不改。

## 分工

根负责 Git 提交推送、全局 CLI 安装、任务收尾与整合。Trellis 实施者负责 Trellis 模板和 Fusion 定制兼容；GitNexus 实施者负责生成技能/指引建议和索引兼容研究；检查者独立验证最终差异。所有文件写入先明确责任，业务源代码不再扩展。
