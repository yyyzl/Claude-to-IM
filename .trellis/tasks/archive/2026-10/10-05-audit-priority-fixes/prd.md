# 审查前三项修复

## 目标与授权

用户明确选择上一轮审查的三个实际问题：补发阻塞、补丁恢复、旧会话找回，并授权建任务、实现、提交和推送远端 main。本任务作为一次发布统一验收，桥接两项共用 manager 生命周期，工作流一项独立并行实现。

## 已确认问题

- R1：`src/lib/bridge/bridge-manager.ts:1008,1905` 在渠道消费循环内等待 `/retry` 网络投递，同渠道其他聊天的 `/stop` 和审批不能及时处理。内存 manager 场景已复现。
- R2：`src/lib/workflow/workflow-engine.ts:914,949,1051` 保存文档后才推进检查点；`patch-applier.ts:136` 的未知标题补丁首次追加且报告失败，恢复对最新文档重放会变成成功，可能错误解决问题。
- R3：`src/lib/bridge/bridge-manager.ts:1882` 的 `/sessions` 只列当前渠道绑定并截断 ID；`/new` 覆盖绑定后旧会话不在列表，显示 ID 不能用于 `/bind`。

## 验收标准

- AC1：一个聊天的补发等待不阻塞同渠道另一聊天停止或权限处理；补发不调用模型，重复重试不并发重复发送。
- AC2：停止、切换会话及桥接停机能取消补发的后续分块；已成功块保留，后续重试只发送未完成块，旧任务不污染新状态。
- AC3：spec/plan 保存、账本保存和步骤检查点前任一受测中断点恢复后，文档、补丁失败判断与问题状态与不中断执行一致；失败不得升级为 resolved，重复恢复不新增文档版本或重复追加内容。
- AC4：当前聊天 `/sessions` 能找到切换前会话，展示可用完整 ID，并能通过现有 `/bind`（支持时使用按钮）切回；不列出其他聊天的历史或当前绑定。
- AC5：会话历史在当前 JSON 宿主重启后保留；对无法可靠判断归属的旧数据不得猜测公开。无历史能力宿主仍有明确的当前会话信息。
- AC6：相关故障回归、typecheck、build、整合单测通过，独立审查完成，GitNexus 检查符合范围，提交推送 origin/main。

## 范围外

不修改提示词预算、状态卡、审批详情、启动脚本、模型目录、Fast、依赖版本或上游功能；不合并 upstream，不启动真实模型/飞书，不重启生产桥接，不更换数据库。
