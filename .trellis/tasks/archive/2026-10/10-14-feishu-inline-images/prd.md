# 修复飞书回复文本与图片混排

## 目标

让飞书收到正文显式引用的本地图片，并在同一回复卡片中保持文本与图片的原有顺序，消除截图中的损坏图片占位。

## 背景与证据

- 用户已同意创建任务，并在最终规划摘要后回复“我觉得没什么问题”，认可本方案进入实现。
- 截图对应 assistant 正文引用 `<G:/project/feishu-notify-design/result.png>` 与 `<G:/project/feishu-notify-design/question.png>`。两张图存在、有效且位于会话工作目录 `G:/project` 内，分别为 860×1800、197056 字节和 860×1280、77655 字节。
- `src/lib/bridge/markdown/feishu.ts:34` 仅处理代码围栏；`:42`、`:64` 原样封装 Markdown。`src/lib/bridge/adapters/feishu-adapter.ts:919` 将未转换的本地图片链接放进最终卡片，未上传图片。
- `scripts/claude-to-im-bridge/codex-llm.ts:585` 仅从当前回合原生 `imageGeneration` 提取图片，`:607` 中的普通工具、`imageView` 不产生图片交付。现有行为不能覆盖截图中的本地图片正文引用。
- `src/lib/bridge/response-delivery.ts:149` 将全部文本排在独立图片之前；`:78` 的流卡收尾只确认文本块。内嵌图片需要完整图文的送达确认。

## 要求

| ID | 要求 |
| --- | --- |
| R1 | 飞书最终回复支持正文真实 Markdown 图片位置中显式引用的本地 PNG，保留文本与图片顺序、原有文本格式及图片说明；优先沿用原完成卡，超限时完整分段。 |
| R2 | 仅读取当前绑定工作目录内显式引用的普通图片文件。支持相对路径、绝对路径及尖括号形式；按真实路径检查边界，排除越界与符号链接逃逸。不读取代码示例、普通文本路径、工具 savedPath 或扫描目录。 |
| R3 | 复用现有 PNG 校验和每图/每轮预算。文件缺失、格式不支持、损坏、越界或超限时，在对应位置给出简明说明，正文仍可交付，不留下损坏图片语法。 |
| R4 | 上传前持久化图文待发材料，上传 key 保存后再发送或收尾。上传/发送失败可 /retry；重试复用保存的图片数据与 key，不重调模型、不依赖原文件仍存在。内嵌图片不得又作为独立图片重复发送。 |
| R5 | stop/new/bind/停机后禁止后续未开始的上传和发送，迟到上传不得触发发送；流卡仅在完整转换后的图文得到平台成功回执时确认送达。 |
| R6 | 纯文本、已有原生生图与其它平台行为通过回归；运行中尚未上传的本地图片使用文字说明，最终转换完成后显示图片。 |

## 验收标准

- [x] A1（R1）：fake 平台复现截图的两图正文，观察同卡图片引用已转换为上传 key，文本与图片顺序一致，响应体中不再出现本地路径图片链接。
- [x] A2（R2/R3）：代码块、行内代码不触发读取；尖括号、含空格、相对路径正确解析；缺失、非 PNG、超限、越界与链接逃逸明确说明，正文保留。
- [x] A3（R4）：第 2 张上传失败与卡片发送失败后补发；重建 store 并移除原文件仍可恢复，已保存 key 复用，已确认块不重复发送。
- [x] A4（R5/R6）：上传挂起期间取消/切换、迟到回执、完成卡成功或降级、纯文本及原生生图回归通过。
- [x] A5：相关 fake 测试、typecheck、build 通过；单测每批硬超时 60 秒，测试不调用真实模型或生产飞书。
