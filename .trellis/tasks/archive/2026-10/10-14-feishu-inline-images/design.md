# 技术设计

## 边界与数据流

1. bridge-manager 只传递当前绑定工作目录和已存在的归属检查，不加入飞书图片解析实现。
2. 投递层通过小型 internal helper 识别当前最终回复中的真实 Markdown 图片，区分本地 PNG 与代码示例。保留原文与图片位置映射；已有 markdown-it 可用于语法识别，禁止对全文做路径正则全局替换。
3. 本地读取按 realpath 比较文件与绑定工作目录；限制文件类型、大小、数量与合计预算后，复用 PNG 校验并形成不可变图片快照。拒绝项替换成对应说明，不保留损坏图片语法。
4. outbox 持久化正文块和内嵌图片快照、位置映射、上传 key。save + flush 完成后才能上传，key 再次 save + flush 后才能进入平台渲染。文本/原生独立图片的旧记录仍可加载。
5. 实际 image_key 替换图片链接后，完整转换正文进入原流卡收尾；fallback 和超限分块发送相同转换正文。确认必须对应图文块而非只有原文字；被正文吸收的内嵌图不再作为独立图片发送。

## 渲染与确认

- 完成卡保留正文顺序，以上传 key 替换本地 src。运行中用图片说明代替待上传的本地图片语法；不在每次增量时重复读取和上传。
- 原收尾回调需要接收投递层准备好的正文，避免闭包继续使用原本地路径文本。纯文本继续沿用现有流程。
- 普通发送时，含转换图片的正文选择支持 Markdown 图片的卡片路径；失败降级不得回到原始本地路径正文。
- 分块预算按实际序列化内容计算，并保证图片标记与引用不跨块损坏。完整卡片确认失败时，保留未确认图文块；已确认原生图片/其它块不重复发送。
- 上传失败期间，用户能看见保留正文和图片待补发说明；该临时展示不能将未完成图文块记为 delivered。
- 失败预览优先通过现有 finalize(previewText) 收尾原卡，返回 true 仅表示该说明卡已收尾，不能确认 outbox；无卡或 false 才独立展示说明。沿用模型回合终态，不新增投递状态回调接口。

## 持久化与兼容

host.ts 的正文块合同增加内嵌图片数据与已上传 key（具体字段在实现时保持最小结构）；宿主 store 对新增结构严格校验、拷贝并恢复。旧文本与独立原生图片无需迁移，原生生成图事件准入规则保持不变。成功记录清除媒体数据。

重试使用已持久化快照，不重新解析或读取本机路径。上传去重可按同图标识/摘要复用 key，但重复引用位置都保留。稳定投递身份包含媒体快照，避免同一文字引用不同文件内容却混用记录。

## 取消与失败

沿用 isCurrent、发送期限与每次副作用前归属检查。上传迟到只能结束原等待，不能自动发送。成功平台回执的进度先落盘，再处理后续取消；结果未知不宣称成功。

## 验证与回退

验证使用合成临时 PNG、fake 上传与卡片传输，不读取用户图片目录做单测。诊断读取实际文件已单独完成。回退以本任务 diff 为边界，保留已有待发记录；不通过删除 store 或强制覆盖索引回退。

真实飞书客户端展示、生产发送与重启服务留待用户单独授权，本阶段只验证结构与状态语义。
