# 飞书查看 Codex 账号额度

## 目标与用户价值

用户在飞书中查询当前桥接使用的 Codex 登录账号额度，看到服务端提供的 5 小时、周或其它窗口的已用比例、剩余比例和重置时间，判断后续工作是否需要等待。

## 背景与已确认事实

- 用户于 2026-10-13 同意创建任务并规划，要求优先接入账号额度。文件双向收发和跨重启去重保留为后续需求，不属于本任务。
- 桥接通过 CodexAppServerLLMProvider 使用 app-server 的 stdio JSON-RPC：`scripts/claude-to-im-bridge/codex-llm.ts:89`、`scripts/claude-to-im-bridge/codex-jsonrpc.ts:239`。
- 本机固定依赖 Codex 0.160.0 的离线生成 schema 包含 account/rateLimits/read，支持单桶、多桶以及可空的周期/重置时间，详见 research/app-server-quota.md。
- `/usage` 是本地 Token 汇总，`/status` 是桥接运行状态，没有账号额度数据：`src/lib/bridge/internal/usage-command.ts:1`、`src/lib/bridge/bridge-manager.ts:1846`。

## 功能要求

| ID | 要求 |
| --- | --- |
| R1 | 新增 `/quota`，只读查询当前桥接 Codex 登录账号额度；帮助提供入口，保留 `/usage` 现有语义。 |
| R2 | 展示各实际额度桶及窗口的已用百分比、计算的剩余百分比、服务端重置时间和查询时间。时间明确使用北京时间。 |
| R3 | 300 分钟显示为 5 小时，10080 分钟显示为周；其它周期按实际时长显示，未知周期明确说明，不按 primary/secondary 的位置猜周期。 |
| R4 | 标注额度属于登录账号、由其它项目和客户端共享；不展示邮箱、账号 ID、令牌、原始响应或付费操作。 |
| R5 | 未提供窗口、不支持额度的账号/后端、未登录、超时、断连、格式错误都有明确说明。空数据不代表剩余 100%，时间到达不代表额度已恢复。 |
| R6 | 复用现有 app-server，不启动模型回合、不创建/切换会话、不改模型、权限、配置或认证，不计入本地模型 Token 用量。 |
| R7 | 模型执行中可查询。额度请求或回执发送不能阻塞后续 stop/new/审批；停机或重启后不发送旧查询回执。 |

## 范围外

自动轮询、预警、自动换模型、暂停模型任务、账号切换、消费重置券或购买积分；原生账号 Token 活动报表；文件收发、跨重启去重与其它命令对齐。本轮规划/自动测试不查询真实账号、不发送生产飞书消息、不重启桥接。

## 验收标准

- [x] A1（R1/R2）：`/quota` 和 `/quota@bot` 返回明确标注账号范围的报告；普通非法参数显示用法，危险输入沿用安全拒绝，帮助包含入口。
- [x] A2（R2/R3）：300/10080/其它/未知周期均正确命名；多桶不重复显示单桶镜像；缺失窗口不虚构比例。
- [x] A3（R2/R5）：0% 已用显示 100% 剩余，100% 及超额显示 0% 剩余；非法比例不得变成 0%；重置时间按秒解释，未知/到期保持诚实表述。
- [x] A4（R4/R5）：能力不支持、RPC 失败、空数据和格式错误均有用户可见说明；私有字段不进入新增正文/日志，桶名称正确转义。
- [x] A5（R6）：fake RPC 只有握手与额度读取，没有 thread/start、thread/resume、turn/start 或账号/配置写入；会话、模型与 Token 统计不变。
- [x] A6（R7）：实际 fake manager 消费循环中挂起查询及发送，后续 stop/new/审批仍可处理；停机/重启后旧结果不发起发送，已经进入平台的请求仍可能完成。
- [x] A7：相关最小单测、typecheck/build 和整合回归通过；后台单测总超时不超过 60 秒。

验收证据：2026-10-13 独立审查相关 13 个文件、203 条测试通过；完整 `npm run test:unit` 790 条通过、约 17.86 秒，外层硬超时 60 秒；typecheck/build 通过。均为离线 fake 验证，真实账号与生产飞书未联调。
