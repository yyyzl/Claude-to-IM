# Codex 生成图片自动回传飞书

## 目标与授权

用户在侧聊明确要求将本需求交给主线程并开发完成（转入消息来源 `01a10811-92a5-71d0-b8f6-79a3ebf8c6e9`）：在飞书要求 Codex/Imagegen 生图后，图片自动发回原聊天，可与文字说明一起返回，无需第二次上传指令。本任务是已授权父任务的新增子项，前三项可靠性修复先独立提交推送，本能力独立实现与验证。

## 已确认事实

- 项目锁定 Codex 0.160.0 原生 app-server 提供 `item/completed` 的 `imageGeneration`，包括本回合 threadId/turnId/item.id 和 PNG Base64 `result`；无需桥接注入桌面工具或升级依赖。
- `result` 可能因媒体省略配置而为空；桥接只使用明确完成事件的数据，不扫描目录，不根据模型文字读取文件，不使用任意 savedPath 回退。
- 当前 Codex 事件转换、会话结果、出站契约和飞书发送尚未贯通图片；已有 outbox、取消及会话代际保护必须复用。
- provider、认证、额度仍由 Codex 控制；静态 capabilities true 不等于真实账号可生图，本任务不声称已做账号验证。

## 验收标准

- I1：正常成功的当前回合生成图自动发到同一飞书聊天；文字与图片都保留，纯图、多图以及流式卡片收尾都不丢图片。
- I2：只处理精确当前 thread/turn 的成功 imageGeneration completed；同 item 重复通知只产出一次。started、failed、imageView、输入附件、历史回合与模型文本路径不能被当成生成图自动发送。
- I3：严格验证 PNG Base64、图片内容和大小；不合法、空数据、超限或上传/发送失败均明确反馈，不谎称图片已送达，不在日志/会话正文记录 Base64。
- I4：文字与图片投递逐块记录成功进度；补发仅处理未确认送达的内容，不重复已送文字/图片，不再调用模型生图。支持 JSON 宿主持久恢复；不绕过现有 outbox。
- I5：stop/new/bind/桥接停机取消后续图片发送，迟到的旧回合产物不发往新会话；已进入平台的请求遵循现有结果未知边界。
- I6：保持其他平台文本行为；不支持图片出站的平台给明确说明，不把路径或Base64作为图片替代发出。
- I7：使用固定0.160.0真实协议结构及合成PNG、fake app-server/飞书客户端与独立临时store验证，无真实付费生图/生产接口；typecheck、build、相关与整合测试通过后独立提交并推送origin/main。

## 范围外

不扫描用户目录、不发送用户任意文件、不读取或修改全局登录/配置，不删除Codex生成原件；不新增模型提供商/图片编辑工具/生图计费或额度管理，不重构完整消息协议、不换数据库，不更改前面已确认的三项修复语义。
