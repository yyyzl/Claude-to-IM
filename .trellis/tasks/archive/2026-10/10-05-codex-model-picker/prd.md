# Codex 动态模型与飞书选择卡片

## 目标

在 Codex 飞书桥接输入 `/model` 后，查看当前配置和实际可用模型，选择模型、推理强度、Fast／正常速度并应用，无需记忆模型 ID 或手工修改配置。

## 已确认背景

- 用户于 2026-10-05 确认配置应由当前飞书聊天记住、在 `/new` 后继承；完整方案已审核，用户明确批准开始开发，实现及离线验收已完成，功能提交为 `d5db4ed`。
- 用户特指 Codex，并观察到默认仍为 GPT-5.5，现有 `/model` 交互不能满足选择需求。
- 仓库已接入动态模型发现（`scripts/claude-to-im-bridge/codex-llm.ts:218`）和文本模型／强度设置（`src/lib/bridge/bridge-manager.ts:1701`），但无参 `/model` 没有选择面板；速度字段尚未贯通。
- `src/lib/bridge/conversation-engine.ts:417` 把实际型号回写选择偏好，会使“跟随默认”固定成具体型号。未读取用户配置及会话，不能断言当前 GPT-5.5 的具体来源。
- 项目锁定的 Codex 0.160.0 离线协议提供模型级 `serviceTiers/defaultServiceTier`，可据此展示真实速度选项；标准速度需显式传 `default`，不能用省略字段代替。
- 官方说明模型和强度依赖客户端与账号，应读取运行时目录，不硬编码官网示例。

## 需求

- R1：无参 `/model` 展示选择卡片和当前生效配置。
- R2：模型选项来自实际 Codex 运行时，提供刷新入口；获取失败明确提示，不伪造可用列表。
- R3：推理强度随所选模型联动，仅展示该模型支持的档位。
- R4：速度独立提供正常和 Fast；表达实际支持情况及 Fast 用量更高的提示，不以降低推理强度冒充加速。
- R5：明确应用后才保存；保存成功后回显，后续请求实际使用所选值。
- R6：回调校验操作者、聊天、会话及卡片有效性，过期或重复点击不能误改其他会话。
- R7：保留文本设置入口，不影响 Claude 桥接。
- R8：提供“跟随 Codex 默认”，明确显示当前解析到的型号；实际请求结果不得覆盖用户的跟随偏好。
- R9：配置由当前飞书聊天持久保存；`/new` 仅清空对话上下文，继续继承所选模型、强度和速度。绑定其他会话也不覆盖聊天偏好，其他聊天互相隔离。
- R10：设置只在下一次请求生效；运行中的任务保留原配置，忙碌期间拒绝应用并给出提示。旧卡、切换会话和重复点击不能意外应用配置。

## 交互决策

- 使用两步原生卡片：模型选择／刷新／跟随默认 → 该模型的强度和速度 → 应用。模型选择的中间步骤不落盘。
- 强度支持跟随所选模型默认；明确选择的档位失效时提示重新选择，不静默降低。
- 速度只涉及正常和 Fast；没有 Fast 能力信息时不提供可用的 Fast 选项。真实服务拒绝时原样给出可操作错误，不虚报成功或自动换模型。
- 只提供聊天级设置，不增加全局／单次／多作用域切换。卡片中显示“当前聊天生效，/new 后保留”。
- 保留 `/model <model-id> [effort]` 和 `/model default`；模型或强度写入前即验证，文字设置也写入聊天偏好。
