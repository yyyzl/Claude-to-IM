# Codex 模型选择设计

## 1. 边界与交付单位

这是一个跨宿主、桥接核心、飞书适配器的完整功能，采用单个任务按层实施。各层必须串联才能验收，不拆成可独立交付的子任务。

- 宿主提供模型目录及 Codex 协议映射；核心通过 `LLMProvider` 正式契约访问，不导入 runner 实现。
- 核心负责配置验证、聊天偏好、卡片草稿和归属；飞书仅负责表单呈现、回调解析与消息更新。
- Claude 路径不启用 Codex 偏好，不改变其模型处理行为。

## 2. 用户流程

1. `/model` 读取当前聊天配置和运行时目录。首张卡显示当前配置、模型下拉框、跟随默认、刷新、下一步和取消。
2. 点击下一步后更新原卡，显示选中模型、其真实支持的强度、正常／可用的 Fast、返回和应用。切换模型后重新验证原强度和速度，失配时要求重选，不能沿用无效组合。
3. 点击应用时重新验证来源、代次、会话、忙碌状态和完整配置。成功保存后显示“当前聊天生效，/new 后保留，下一次请求使用”。
4. 目录获取、投递或保存失败给出错误；取消、过期、重启后的旧卡不更改配置。卡片更新失败与配置保存失败分开报告。

使用现有 schema 2.0 `form/select_static/submit`，避免依赖尚未确认的表单内即时联动。卡片草稿含 revision，返回／刷新后旧步骤的迟到事件必须拒绝。目录选项按平台数量及序列化大小限制分页，分页只影响呈现，不截断真实目录。

## 3. 配置与持久化

在共享 `ChannelBinding` 增加可选的结构化 Codex 聊天偏好（建议名 `codexModelPreferences`）：

```typescript
interface CodexModelPreferences {
  model: string; // 精确目录ID，或 default 表示跟随目录默认
  reasoningEffort: string | null; // null 跟随该模型默认
  speed: 'normal' | 'fast';
}
```

- 这一个对象是用户显式设置的唯一来源，按 `channelType + chatId` 所属 binding 保存。优先复用 `updateChannelBinding`，不增加新存储表或全局设置。
- `model/reasoningEffort` 旧字段及 session 模型状态不得再反向覆盖该偏好。实际模型状态单独用于运行信息；界面区分选择偏好、解析结果和上次实际值。
- `/new` 继承偏好，SDK session 仍须清空；`/bind` 保留当前聊天偏好，不从历史 session 导入设置。后端为 Claude 时不应用这些 Codex 字段。
- 未含新字段的旧 JSON 正常读取，不把历史型号猜成用户新选择，也不自动升级到别的型号。旧数据在用户首次应用卡片或文字命令后建立完整新偏好。新偏好存在时不再同时维护第二套覆盖规则。
- 显式 `model: default` 必须走目录默认，不被旧的 model hint 或上次运行结果替换；尚未显式设置的旧路径保留原有宿主配置优先级。
- 显式强度不支持时拒绝，`null` 每轮解析到当前所选模型的目录默认。默认模型后续变化导致显式强度／Fast 不兼容时，报告重新选择，不静默换配置。
- 速度未显式设置的旧数据显示“运行时默认／未指定”，不能虚构为正常或 Fast。完成新卡片时明确选择正常／Fast。
- 一次更新完整偏好对象并等待现有 store.flush 成功再回显持久保存。失败时恢复本次内存修改（需校验版本以免覆盖其他更新），不启动模型请求、不宣称已持久化。不支持 flush 的第三方宿主仅能报告其实际保存保证。
- runner 复用或同步正式 binding 类型，消除缺失 reasoningEffort 等契约漂移；不复制新的偏好类型。

## 4. 目录与 Codex 传参

`LLMProvider` 增加可选目录能力，返回规范化的模型 ID、显示名、默认项、默认／支持强度及速度能力。只读目录方法允许强制刷新，Codex 复用现有连接初始化与 model/list 分页。

- 初始化与刷新分别管理并发 promise；完整分页验证成功才替换缓存。刷新失败不得破坏正在执行的其他聊天或重置已初始化连接。
- `/model` 每次请求目录；短时间重复请求合并，刷新入口明确强制重新读取。返回数据验证形状、ID、重复项和游标，不靠 TypeScript 断言信任外部数据。
- 基于当前目录校验卡片及文字设置；开始真实请求前仍复验，处理保存后目录变化。
- 目录 `serviceTiers` 中明确提供 Fast 才开放 Fast。标准速度由协议定义，不用把缺少 Fast 元数据误判成支持 Fast。
- 发送 `turn/start.serviceTierForTurn = 'default'` 对应正常，Fast 使用目录实际支持的 `fast` ID；所有采用新偏好的请求都显式发送速度。不要用省略或 null 退出 Fast。
- `model`、`effort` 和速度来自同一个已验证配置快照；`thread/resume` 后的新 turn 也必须发送。不会修改正在运行回合，也不增加 thread/settings/update 的副作用。
- 无需更改用户全局 config.toml。真实账号可能因策略拒绝 Fast，应呈现真实错误；schema 不证明账户授权或服务端接受，不自动切到正常重试。

## 5. 核心、适配器和安全

核心新增小型模型选择协调模块，避免把整个表单状态机塞入 `bridge-manager`。适配器增加可选模型卡发送／更新能力，入站使用独立 `modelSelectionResponse`；保持现有问答和权限 broker 独立。

草稿至少记录随机 requestId、聊天／用户、sessionId、binding ID、run epoch／chat generation、原卡 messageId、revision、到期时间、状态和所选值。服务端状态是归属依据，按钮携带的会话标识不可信。使用合理有界 TTL（默认10分钟）及每聊天一个活动草稿，避免无限积累。

- `handleCardAction` 先校验飞书提供的真实 context/operator 和 allowlist，解析表单后快速入队，不能同步等待目录网络请求。
- `runAdapterLoop` 将模型卡回调归入控制消息分支，不进入普通模型对话队列。
- 核心应用串行化，同一聊天的新消息准入、应用、new/bind/stop 不能出现检查后竞态。异步 await 后重验归属及忙碌状态。
- 只有发起卡片的用户可应用。重复提交只有一次有效写入；过期、跨用户／聊天／消息、切走再切回均拒绝。
- stop/new/bind/bridge restart 使旧草稿失效；晚到的卡片创建／目录结果不登记为新会话草稿。配置偏好继续保留。
- 用户任务执行中可查看目录，但应用拒绝并提示等待或停止；不为了改配置中断任务。

## 6. 文字入口与显示

- 保持 `/model <id> [effort]` 和 `/model default` 可用，Codex 走相同目录校验及完整偏好保存。省略强度表示跟随模型默认；速度沿用已有显式偏好，未设置时选择正常并在回执说明。保留的 Fast 与新模型不兼容则拒绝并提示打开卡片。
- 无卡片能力的适配器继续提供文字结果，不新增其他平台的原生 UI。Claude 旧入口保持原行为。
- `/status` 与卡片使用一致的偏好／实际状态展示，不能因为 session.model 优先而显示旧型号。
- 帮助和中文文档同步说明两步卡片、继承、默认项、忙碌限制与 Fast 用量提示。

## 7. 风险、验证与回退

GitNexus 预查命令入口 handleCommand/handleMessage 为 CRITICAL，涉及消息入口和调度；用户已被告知。正式实现前仍逐符号运行 impact，并结合源码处理图中的同名误连，不能假定预查覆盖所有新修改。

离线验证：目录分页／并发刷新、无效组合不写入、默认不固定、偏好重启／new／bind 保留、卡片归属和竞态、正常覆盖 Fast、存储失败，以及既有 Claude／权限／问答／停止回归。最终 typecheck、build 与相关单元测试通过；每次后台单测最长60秒。

生产验证边界：不自动重启桥接或发测试飞书消息。真实卡片呈现和账号 Fast 可用性需在获准的使用中观察，交付不能声称离线验证已覆盖它们。

回退不删除用户 JSON：新增字段为可选，旧程序可忽略；代码回退保留现有偏好数据。所有失败均不自动替换模型、不调整全局依赖或账号设置。
