# 升级模型运行时与飞书交互卡片

## 目标与授权

用户在已完成的升级评估基础上，要求实际更新应更新的依赖、适配模型，并检查、改进飞书新版卡片处理。本任务实施并验证这些改动。

实施期间用户补充授权：“包括 Code s 该升级也可以升级，这几个都是该升级可以升级”。因此范围扩展到已确认由 npm 全局安装的 Codex CLI 与 Claude Code 更新，以及 Codex 桌面版可用更新检查；不延伸至无关全局软件。

## 范围

1. 项目局部运行时：Claude Agent SDK 0.3.289 及必要 peers、飞书 Node SDK 1.74.0；项目固定 Codex CLI 0.160.0 并优先解析项目局部二进制。全局安装与运行中的桥接不作为实现前提。
2. Codex：双向 JSON-RPC、initialized 握手、审批与问答、每会话模型/权限、目录提供的 effort、恢复、真正中断、失败终态、现代工具与用量事件、图片输入和日志脱敏。
3. Claude：使用目标 SDK 的公开入口和实际类型，正确处理工具结果、任务进度、用量与图片输入；交互式问题回传实际答案；明确权限和设置加载策略。
4. 模型/工作流：移除退役默认模型及按字符串偏好旧 Codex 型号的逻辑；修复 spec-review 模型覆盖与 AutoFixer worktree cwd；保留已有审查/修复策略。
5. 飞书：基于现有 schema 2.0 + CardKit 实现改进流式更新、收尾与错误恢复；改进审批与问答卡片，正确回传回调；以已核对的官方 API 为依据。
6. 质量：集成 scripts 与 tests 的类型/测试检查，必要的协议、交互、卡片和工作流回归；同步使用文档。

## 约束

- 保留 DI 边界与多平台适配能力；不为本任务重写整个工作流引擎。
- 不读取或修改凭据，不调用生产接口，不发送真实飞书消息；使用 mock 验证 API 契约。
- 根据追加授权更新 Codex CLI / Claude Code 全局安装；不更改系统权限或凭据，不重启当前运行中的桥接。
- 不静默替换用户指定的无效模型，不以模型目录作为实际账号 entitlement 证明。
- 不长期保留已明确过时的兼容分支；在所支持运行时范围内使用公开协议。
- 修改现有符号前运行 GitNexus upstream impact；图错误以源码补充，HIGH/CRITICAL 先告知用户。
- 测试单次后台执行最长 60 秒，按相关组运行；失败后有针对性修复。

## 验收标准

- [x] 目标依赖安装、lockfile 一致，项目运行时和全局软件版本边界明确。
- [x] Codex 服务端请求不再丢失或串入本地主动响应，审批/用户答案可回传。
- [x] /model、/mode、恢复、取消、失败状态按实际后端行为工作。
- [x] 模型与思考强度使用目录能力，不默认选择退役模型；附件明确支持或明确拒绝。
- [x] Claude SDK 适配器的工具结果、进度、输入与错误通过真实形状的 mock 回归。
- [x] 飞书卡片更新遵循官方顺序/频率/收尾语义，不因竞态把完成卡覆盖为旧内容。
- [x] 工作流模型覆盖与修复 cwd 正确，现有工作流行为回归通过。
- [x] 类型检查、构建、相关单测通过，文档包含权限/版本/部署注意事项及未联调边界。
