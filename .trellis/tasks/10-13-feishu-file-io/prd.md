# 飞书文件双向收发

## 目标

用户在飞书取得当前会话明确指定的普通文件产物，并能发送文本、CSV 等材料供模型处理。先交付文件回传，再交付文件输入；文件传输与内容解析分别验收。

## 已确认事实

- 用户已授权此功能，沿用先回传、再输入的调研方案。
- 飞书入站仅接文本/图片，普通 file 消息会明确提示不支持：`src/lib/bridge/adapters/feishu-adapter.ts:1515`。
- Claude 和 Codex 现有文件输入仅支持图片：`scripts/claude-to-im-bridge/llm.ts:41`、`scripts/claude-to-im-bridge/codex-llm.ts:268`。
- 现有图文待发/补发提供持久进度与停止归属：`src/lib/bridge/response-delivery.ts:124`。
- 上游 PR #31 有 40 个文件且包含多机器人、微信和 SDK 迁移；其 Edit/kind=create 文件识别不覆盖我们所有产物生成方式。

## 要求

| ID | 要求 |
| --- | --- |
| F1 | 回传用户明确要求、能证明属于当前会话的指定文件；支持通过脚本生成的普通文件，不依赖扫描修改文件或解析任意回复路径。 |
| F2 | 普通文件复用已有 outbox 和 /retry，保留上传 key、发送身份及已确认进度，补发不重新生成。 |
| F3 | 停止/新建/换绑/停机阻止后续未发起的上传与发送；已进入平台的请求保持结果未知语义。 |
| F4 | 先接收文本/CSV 等可验证材料，保存并提供当前会话可访问的文件内容或路径；部分失败明确列出未读到的材料。 |
| F5 | 保留原图片输入与原生生成图回传；文件路径、大小、类型、空文件、缺失、被修改或越界均明确处理。 |
| F6 | PDF/Word/Excel 的解析依赖单独核实后端工具能力；支持接收不等于支持解析，未验证格式不声称已理解。 |

## 验收

- [ ] A1（F1）：明确指定的 CSV/报告/表格等实际文件可回传原聊天；脚本生成也可使用，未指定文件不自动上传。
- [ ] A2（F2）：上传/发送失败及重启可补发同一文件，部分成功不重发已确认内容，不重新调用模型。
- [ ] A3（F3/F5）：stop/new/bind/停机、文件变化、大小超限和路径归属失败均有可观察结果。
- [ ] A4（F4）：文本/CSV 文件实际内容到达正确模型回合；同轮多附件和部分失败不静默丢材料。
- [ ] A5（F5/F6）：已有图片能力正常，格式不支持/解析失败如实说明。
- [ ] A6：fake 平台与 fake 模型的相关测试、typecheck/build 通过，单测批次硬超时 60 秒。

## 范围外

多机器人、微信、其它 IM 的文件实现、全媒体解析器、自动发送所有创建文件、扫描工作目录、SDK 替换和批量升级依赖。生产联调和重启另行安排。

## 尚待用户选择

首版回传入口采用自然语言指定并由本轮受限声明工具登记，还是 /sendfile 显式命令。入口选择会影响后端工具协议及旧 Codex 会话兼容，未确认前不将其中任何一种视为已批准。旧会话恢复接口没有 dynamicTools 参数，不能自动新建会话替代。
