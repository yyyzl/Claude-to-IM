# 飞书 Codex 非阻塞问答与迟到答案补充

## 用户需求与授权

用户希望在飞书回答 Codex 的选择题和输入题，包括 Codex 提问后仍继续工作的情形。2026-10-14 已展示研究结果及方案：有效答案回传原请求；原问题关闭后，由用户明确选择将原题与答案作为任务补充。用户随后回复“可以的，你调研完成以后，就按照你的思路去做吧”，批准该范围的任务规划与实施。

## 用户可见行为

- 问答卡支持现有选择与文字输入；阻塞问题说明正在等待回答，非阻塞问题说明 Codex 仍可继续工作。
- RPC 原问题仍有效时，提交答案回传原请求；原生异步消息题目没有回答 RPC，答案携带原题进入现有任务追加流程。运行中即时追加继续使用原过程卡。
- 原问题已由服务端关闭或原回合正常结束时，说明原问答已关闭，提供显式“作为任务补充发送”入口；内容包含原问题与用户答案。
- 同一原聊天、原发送者、原绑定和会话仍有效时，补充沿用现有即时追加或后轮路径及其设置。即时追加成功继续使用当前过程卡；模型已经结束时进入一次后轮。
- 每个问题组只能成功提交或移交补充一次。明确失败、结果未知、过期和取消不能伪称成功，未知结果不能自动重复发送。
- stop/new/bind、桥接停机和跨用户/跨聊天/伪造卡片使旧问题失效；秘密输入仍要求在本地完成。

## 验收

- [x] 非阻塞问题期间有模型输出，卡片收到正确状态，运行状态不误报等待；阻塞问题及工具审批维持真实等待。
- [x] 选择、自由输入、其他选项、多问题的有效回答只回传原 RPC，重复点击不再次响应。
- [x] 新回合初始化期间收到旧回合问题，不创建问答卡；合法 early 问题须待本轮 ID 确认，等待期间关闭/取消/失败不复活。
- [x] 原问题关闭后的有效补充包含服务端原题与经过校验的答案，运行中即时追加一次，结束后后轮一次。
- [x] 点击原“提交答案”但请求已关闭时，不能自动转为补充；只有显式补充动作才准入。
- [x] 未回答关闭记录有时间和数量上限；已回答、秘密问题、失败投递和取消记录不能提供补充。
- [x] 控制消费循环在补充 RPC、卡片更新或通知阻塞时，仍能处理其他聊天和停止指令。
- [x] 原追加、权限、额度、模型设置、图片、投递、会话控制测试不退化。
- [x] 仅使用内存模型和平台验证；每批后台单测外层硬超时 60 秒。

## 范围约束

本批只处理飞书 Codex 问答。保留既有其他渠道问答和审批合同，不升级 Codex、SDK 或全局依赖，不实施去重/文件任务，不承诺重启后继续回答旧卡片。真实验收仅由主会话在原项目聊天执行，实施/检查代理仍禁止真实接口及重启。用户此前对上一个追加任务的提交推送授权不视为本批的新提交授权。
