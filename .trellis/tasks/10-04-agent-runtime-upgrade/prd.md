# Claude Code 与 Codex 新版升级评估

## 目标

基于当前项目实际接入方式、本机运行时和官方现行文档，评估 Claude Code 与 Codex 更新后的升级路线，重点关注 Codex。

## 已知事实

- 项目包含 IM 桥接库、飞书宿主脚本和 Claude/Codex 双模型工作流。
- 用户本轮请求评估“应该怎么升级”，尚未指定实施范围。
- 本机 Codex CLI 为 0.156.1；Claude Code 为 2.1.198。
- 项目已使用 Codex app-server，并非只有旧版命令行调用。
- 本轮仅保存评估资料，不更新依赖、不改业务代码、不启动生产桥接。

## 临时假设

- “两个软件”指 Claude Code 与 Codex。
- 优先评估飞书远程使用 Codex 的兼容性和体验，同时检查工作流复用边界。

## 交付要求

- 区分已接入能力、确证缺口和需验证风险。
- 建议需对应具体文件或符号，并说明影响链路。
- 官方信息提供来源，记录本机与依赖版本的证据边界。
- 按兼容性基础、能力补齐、工作流整合三个层次给出升级建议和验收标准。

## 验收标准

- [x] 现有 Claude/Codex 接入及版本基线明确。
- [x] 新版官方协议与当前代码差异明确。
- [x] 分阶段方案包含优先级、风险和最小验证。
- [x] 研究结论保存到 research/。

## 评估结果

- 完整路线：research/upgrade-roadmap.md。
- 本轮 typecheck 通过，四个纯 mock 测试文件共 18 个测试通过。
- 优先修复 Codex 双向 JSON-RPC、权限模式、失败状态和会话生命周期；随后升级项目 SDK 及模型配置，再整合工作流执行层。
- GitNexus 部分索引能力退化，调用图不能替代源码核查；审计记录须保留证据边界。

## 本轮范围外

- 全局安装、权限配置、数据库改动。
- 发布、部署、生产 API 调用。
- 无关架构重写和业务实现。
