# 飞书跨重启入站消息去重

## 目标

飞书重复推送同一消息时不重复调用模型或执行指令；这一约束跨正常重启保持。失败和处理中断不能被伪装成已完成。

## 已确认事实

- 用户已授权推进此功能；在即时追加子任务验收后、文件收发前交付，继承已接受补充属于原回合的来源关系。
- `FeishuAdapter.handleIncomingEvent` 使用内存 seen/inFlight，处理入口结束后记 seen：`src/lib/bridge/adapters/feishu-adapter.ts:1435`。入口结束只代表已解析/入队，不代表模型工作完成。
- JSON 宿主 dedup Map 未序列化：`scripts/claude-to-im-bridge/store.ts:334`、`:490`。只替换成 checkDedup/insertDedup 不能实现跨重启保证。
- 当前故障重投已有回归，须保留：`src/__tests__/unit/bridge-feishu-reliability.test.ts:88`。
- 上游 PR #19 在业务处理前 insertDedup，不能直接套用。

## 要求

| ID | 要求 |
| --- | --- |
| D1 | 以平台、聊天和消息身份区分入站记录，重复事件合并为同一次处理。 |
| D2 | 持久化区分待处理、处理中和完成结果；入队或下载失败不视为模型处理完成。 |
| D3 | 重启后已完成记录不触发模型；已生成回答但投递失败沿已有 /retry 补发。 |
| D4 | 异常中断的执行结果未知须明确呈现；恢复策略在设计中单独说明，不承诺跨平台 exactly-once。 |
| D5 | 保持停止、新建、换绑、审批、追加排队等既有生命周期；记录大小/保留有界。 |

## 验收

- [ ] A1（D1）：同进程并发和串行重投同一事件，模型执行计数为一次。
- [ ] A2（D2/D3）：实际 JSON 保存后重新构造宿主并重投，已完成消息不再执行。
- [ ] A3（D2）：下载、持久化或入队失败不永久抑制后续合法重投。
- [ ] A4（D3）：模型完成、回答待发时重启或重投不重新调用模型，/retry 可补发。
- [ ] A5（D4/D5）：排队/执行阶段中断、stop/new/bind 和旧回执按明确恢复合同处理。
- [ ] A6：相关离线回归、typecheck/build 通过；后台单测每批硬超时 60 秒。

## 范围外

其它 IM 平台、多进程共享执行、SQLite 迁移、平台永久去重承诺、由独立即时追加子任务承担的执行方式修改。生产联调和重启不在自动测试中执行。
