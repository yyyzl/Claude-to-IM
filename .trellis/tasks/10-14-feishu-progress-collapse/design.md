# 飞书实时进度与历史折叠：技术设计

> 当前展示布局以 [完成卡设计及S8决定](design-S7.md) 为准：运行时3个固定叶子，成功终态只保留答复与唯一状态/耗时，移除整个过程面板。下文7叶子与6个非正文恢复描述保留为先前实现记录；非正文叶子动态推导，并保留S6b预算恢复语义。

## 授权与边界

用户已审阅“当前动作与最近进展常显、旧过程折叠、最终回答优先、超限完整分段”并明确要求“按照这个去优化一下吧”。本设计落实这一已批准方案，不改变模型、宿主或投递合同。业务修改限于飞书适配器和 Markdown 渲染；允许将新增纯展示逻辑放进同目录 `feishu-progress.ts`，避免适配器承担预算和排版细节。

输入只有 ToolCallInfo 的 id/name/status 与最新 progress 字符串，没有完整 stdout、工具耗时或结构化阻塞原因。不得冒称已保存完整日志，不推测百分比、剩余时长或特定等待原因。问答与审批卡继续独立显示。

## 固定卡片与局部更新

初次创建固定正文、任务状态、最近进展、历史摘要、折叠面板及内部历史 Markdown、追加提示、最终页脚。面板使用官方 `collapsible_panel`，只在创建时设置 `expanded:false`。各 element_id 同卡唯一、字母开头、最多20字符。面板标题固定，动态数量放在外部摘要中。

真实平台对照发现：settings修改摘要、settings或batch切换streaming都会重置展开状态；仅子元素partial更新能保留。用户明确选择保留展开状态并接受取消逐字动画。因此初建 streaming_mode:false，摘要用中性固定文案，正文和各Markdown统一走batch partial_update_element。运行与收尾均不写配置、不调用content打字机API、不替换面板或整卡，也不patch面板header/elements/expanded。收尾只改正文、状态、历史与页脚；保留单实际在途、节流、退避与5秒真实耗时。清理被替代的流式双请求/配置收尾分支和冗余状态。

官方没有展开状态回调，也没有承诺局部更新一定保留所有客户端阅读状态。原会话飞书网页版已实测非流式子元素更新与局部收尾保留展开，证据见research/live-collapse.md；新生产实现完成后还须核对真实操作与其一致。不能推广为所有客户端或滚动位置保证。

## 真实进度与预算

默认保留最近3条实际发生变化的工具进展；正在执行与失败数量保持外显，最新动作与错误保留可读摘要。完整命令放入历史。历史按最近真实变化排序，同一重复快照不伪造新事件。manager 原地修改对象，适配器保存不可变字段快照及本地变化序号。

当前状态和真实经过时间外显；每5秒尝试刷新耗时，复用既有调度、串行写入、频控退避，不旁路发送请求。定时器 unref，绑定当前卡片实例；finalize 在等待 in-flight 前清理，cleanup、换代、stop 一并清理。空闲时显示“任务进行中”等诚实状态，有 running 工具时可显示正在执行/等待工具结果，不将心跳计为真实进展。

折叠不会减少 JSON 字节。维持30,000字节保守预算，对实际序列化卡片/请求测 UTF-8（包含转义）；正文预览与进度共享预算，先压缩旧历史/冗长命令，并明确说明仅保留最近内容或摘要，不能因大历史 return 导致状态停更。最新进度、错误、追加提示优先。最终正文不截断：若最终正文连必要卡片框架都放不下，返回 false 交给现有 response-delivery 完整分段/outbox/retry，不重跑模型。状态/历史压缩不能使原本可容纳的最终回答无谓降级。

## 执行流及风险

GitNexus 精确影响已存 research/impact-before.json。buildToolProgressMarkdown 上游 CRITICAL，createStreamingCard/flushCardUpdate HIGH；已在修改前向用户说明。直接调用包括 buildFinalCardJson、flushCardUpdate、onMessageStart/onProgress/onStreamText、scheduleCardUpdate、onToolEvent、onStreamEnd。公共 hooks 静态 UNKNOWN 已由 BaseChannelAdapter、manager 动态调用源码及既有集成测试补证，不能视为低风险。

只调整飞书展示，不修改共享 manager/provider/host 类型。删除被新收尾替代的旧整卡渲染入口、打字机请求路径及无用逻辑，相关测试迁移到实际生产使用的渲染/收尾行为，不为旧测试保留死导出。

## 验证与回退

先观察 RED 再实现：固定面板局部更新、真实最近排序与不可变快照、大历史+中文/emoji/JSON转义预算、错误常显、耗时计时与全部清理路径、最终回答和 ctx 页脚、超长最终正文返回 false、禁止content/settings/config更新、串行与频控、追加/问答/取消/换代隔离。

所有后台测试外层进程树硬截止60秒，node 单测15秒。相关回归通过后一次全量单测、typecheck、build、独立 trellis-check 与 GitNexus detect-changes/实际 diff 核对。当前未授权提交推送、不重启当前自托管桥接进程。回退为恢复本分支业务改动并重新构建；不涉及存储或配置迁移。

## S6 完成态残留的修正边界

用户重启后指出最近3条仍外显。正常成功路由已清空recent，但两处不足已确认：运行batch部分应用后返回失败，旧sentView可能仍空，终态diff漏发清空；completed仍外显工具error摘要，即使任务已成功恢复。当前无法视觉复验，不能将这些源码边界假称现场唯一原因，也不能猜空白Markdown被平台忽略。

最小修正围绕成功完成时显式清空tool_progress，不依赖缓存相等判断，先清理再写其余终态内容；completed的工具错误仅留历史，error/interrupted仍外显必要失败。正文、历史父面板、正常进度、单在途、预算和完整投递合同不变。不泛化为对不确定缓存排序的整卡强制重写，避免引入额外中间超限风险；如实现发现必须扩大恢复范围，先提出证据与设计。

## S6 独立复查补充：不确定运行更新的有界收尾恢复

真实Adapter已证明：部分运行batch可能使平台历史比sentView更长，终态目标历史与旧缓存相同时仍须缩减；仅明确清空tool_progress不足以保证正文写入时的逐步实体预算。不能按旧缓存盲目强写目标历史：终态正文更短时，目标历史可能增长并挤占尚未缩减的旧正文。

仅对运行batch异常或非零后标记viewUncertain；之后普通diff成功也不能证明所有旧残留已恢复。终态先串行清空6个非正文Markdown（近期进展优先），每一步均不增实体、保留原正文；成功并确认generation仍有效后，再以已确认空白基线强制写完整目标，正文首条，其余目标只从空白增长。每批独立在30KB请求预算内，实体从空白基线到已预算目标单调增长。正常路径仍为S6单批收尾，不增加平台请求。失败/中断恢复其必要提示；清理或目标写入失败均不确认完整回答，保持既有false回退。

只改适配器状态初始化、运行flush失败标记和终态恢复，并补真实可达回归、频控和两批之间换代取消。父panel、config、模型调用和投递接口不变。不确定更新后的恢复可能使已展开历史子文本在两批间短暂空白，但不切换展开状态，第二批恢复预算内历史。HIGH/CRITICAL新鲜impact及取舍已在实施前告知用户。
